# MetaForge Agent 面试 PPT 学术版改版规格

## 沟通目标

面向 Agent 开发岗位面试官，在 7–8 分钟内说明制造排程智能体的业务背景、系统架构、任务编排、工具治理、上下文工程、动态重调度和工程难点，并用真实代码与评测数据支撑结论。

## 视觉规范

- 采用 16:9、浅色学术汇报风格，白色或极浅灰背景。
- 主色为深蓝 `#1A3C8B`，正文为深灰 `#253247`，辅助线为浅蓝灰 `#D8E1EE`。
- 橙色 `#D9772B` 仅用于 HITL、风险或当前执行步骤；成功状态可使用低饱和绿色 `#2F7D5B`，禁止多色卡片并列。
- 标题使用概括性的技术模块名，不使用口号、反问、宣传式结论或课程式标题。
- 页面主体优先采用层级架构图、任务时序图、工具执行链、上下文数据流和重调度状态流；表格仅用于职责、能力和评测口径。
- 取消大面积圆角卡片、胶囊标签和数字仪表盘效果；改为平面分区、细线框、箭头和编号节点。

## 页序与标题

1. 制造排程智能体系统
2. Multi-Agent 两层架构
3. Plan-and-Solve 任务编排
4. Function Calling 与 Tool Contract
5. Memory 与 Context Engineering
6. 动态重调度流程与评测
7. 代码实现与工程难点
8. Supervisor 与 Agent 职责（Backup）
9. Tool、策略与求解器接入（Backup）
10. HITL 与异常治理（Backup）
11. 评测设计与结果（Backup）

## 关键图示

- 第 1 页：业务请求到 Agent、Solver、排程结果的四段闭环。
- 第 2 页：Router、六类业务 Agent、Scheduling Supervisor、三个域内分析 Agent、Tool/Solver/Memory 的两层架构图。
- 第 3 页：Route、Plan、Preview、HITL、Execute、Trace、Summarize 的执行时序，并附设备故障任务链。
- 第 4 页：JSON Plan 经 Parser、白名单、Schema、Policy Gate、ToolExecutor 到业务 Tool 和求解器的执行链。
- 第 5 页：Session、Task State、Business Facts 三类上下文进入 Context Compiler，再流向规划与执行；回写仅保留任务状态和摘要。
- 第 6 页：设备故障事件从执行态读取、冻结已完成工序、构建 R0/R1/R2、重排、确认落库的状态流；右侧保留分层评测表。
- 第 7 页：代码片段与 Parse、Execute、Persist 三阶段工程约束关系图。
- 备份页使用职责矩阵、能力接入图、异常处理泳道和评测表，不使用彩色信息卡阵列。

## 内容边界

- 保留 7 页主讲、4 页备份和逐页演讲备注。
- 保留真实代码路径及 `[Sources]` 备注。
- 保留 30→34 Tool、6×14 策略与求解器、8 类事件、R0/R1/R2、L2/L3 评测口径。
- 不新增未经项目文件证明的指标，不把 Preview、全量执行、跳过用例和“Tool 100%”混为同一指标。

## 验收标准

- 11 页均可编辑，标题不换行且符合技术主题命名。
- 至少 6 页以流程图、架构图、时序图或状态流为主视觉。
- 除封面外不出现三种以上强调色并列；无宣传式或课程式标题。
- 每页完成全尺寸渲染检查，无非预期重叠、裁切和越界。
- WPS Office 12.0 可以打开，页数和图形对象可读取；WPS 另存后的 PPTX 通过溢出检测。
