## 2. 总体改进目标（分层）

### 2.1 产品目标（面向车间管理）

- **可用**：输入订单/工艺/资源 → 一键生成可执行排程
- **可控**：规则/权重可调，排程结果可解释、可复现、可回滚
- **可变**：支持插单、延期、故障、缺料等变化触发“局部修复/全局重排”
- **可承诺**：能给出每单预计完成时间、延期风险与影响范围

### 2.2 技术目标（面向后续演进）

- **数据模型清晰**：订单、工艺、资源、日历、事件、任务都能落库并版本化
- **调度目标可扩展**：从单目标 makespan 过渡到多目标可组合
- **计算可扩展**：支持异步任务、并发控制、缓存、可观测性

## 3. “多目标权重”说明（当前策略配置需要写清楚）

新版前端“策略配置”里已有 `weights`，用于计算每个算法的综合评分 `score`（越小越好）。该综合评分是多个目标的加权和：

> **score = w1*makespan + w2*weighted_tardiness_total + w3*energy_cost + w4*machine_busy_cv**

### 3.1 各目标含义

- **makespan（完工时间）**
  - 含义：全部工单完成的最晚时间（越小越好）
  - 业务意义：整体交付速度/产线周期

- **weighted_tardiness_total（加权交期违约）**
  - 含义：每个工单 \(T_i = max(0, C_i - D_i)\) 的违约时间之和，并按工单优先级加权
  - 业务意义：优先保证急单/重要客户按期交付
  - 备注：当前 `Job.due_date` 自动按工序总工时 * k 计算（后续可改为真实交期字段）

- **energy_cost（能耗成本）**
  - 含义：按 `machine_powers(kW)` 与 `hourly_prices(分时电价)` 对每个工序占用的时段积分，估算成本（越小越好）
  - 业务意义：通过排程把高耗能工序尽量排到低价时段

- **machine_busy_cv（负载均衡系数）**
  - 含义：各机台忙碌时间的离散系数 \(CV = std/mean\)（越小越均衡）
  - 业务意义：避免“某台爆炸、某台闲置”，提升产线稳定性

### 3.2 默认权重建议（可作为 UI 提示）

- **默认（综合平衡）**：
  - makespan=1.0
  - weighted_tardiness_total=0.5
  - energy_cost=0.05
  - machine_busy_cv=10.0

### 3.3 调参建议（业务导向）

- **以交付为王（急单多）**：提高 `weighted_tardiness_total`
- **以成本为王（电价波动大）**：提高 `energy_cost`
- **以稳定为王（瓶颈明显）**：提高 `machine_busy_cv`
- **以吞吐为王（订单爆发）**：提高 `makespan`

> 注意：**GA / SA / TS / ACO** 与 **规则启发式** 在传入 `weights` 时已用多目标评价。Q/DQN/PPO 等仍以 makespan 或原逻辑为主。

## 4. 功能路线图（建议迭代顺序）

### 里程碑 M1：数据建模补齐（让系统“可用于真实生产口径”）

- **订单模型增强**：交期、客户、批次、BOM/物料需求、优先级规则
- **工艺路线建模（Routing）**：
  - 产品 → 工序序列 → 可选设备组 → 标准工时
  - 允许“替代机台/并行工位”
- **资源建模**：
  - 设备能力/状态/日历
  - 人员技能/班次
  - 物料到货/安全库存

验收标准：
- 不再需要在工单里手填 `machine_id` 才能排程；可选择“工艺路线+资源组”自动映射

### 里程碑 M2：规则/权重真正驱动排程（从“比一比”到“按策略求解”）

- 将权重（或规则）注入核心评价函数/搜索过程：
  - 在启发式与局部搜索阶段使用多目标增量代价
  - 将 energy/交期/均衡纳入邻域选择或适应度函数
- 支持“策略模板”：交付优先/成本优先/均衡优先

验收标准：
- 在同一数据集上，调权重能稳定地改变输出排程特征（不是只改变排名）

### 里程碑 M3：动态调整与插单（文章的关键价值点）

- 引入 `events`：插单、改交期、设备故障、缺料、人员缺岗…
- 支持两种重排模式：
  - **局部修复**：冻结已开始工序，仅重排未开始部分
  - **全局重排**：允许整体调整
- 输出“影响评估”：哪些订单延期、延期多少、瓶颈在哪里

验收标准：
- 插单/故障发生后 1 次操作可得到新排程 + 影响报告

### 里程碑 M4：交期预测与承诺（对外可解释）

- 输出每个订单的：
  - 预计完成时间
  - 置信区间/风险等级（基于缓冲、瓶颈、负载）
  - 变更导致的承诺变化记录

验收标准：
- 业务用户能用系统回答“这单什么时候交付、风险在哪里”

## 5. 工程化与性能（贯穿式改进）

- **计算异步化**：把排程任务从同步接口升级为 `submit/status/result`
- **可观测性**：耗时、输入规模、算法参数、异常栈、结果摘要落库
- **缓存与复现**：相同输入 + 相同参数可复现同结果；关键随机种子可控
- **权限与审计**：最小权限的鉴权 + 操作日志
