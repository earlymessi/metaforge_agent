## 2. 产品概述

### 2.1 一句话定义

**面向离散制造车间的 AI 辅助排产与制造执行（MES）平台**：以作业车间调度（JSSP）为内核，结合元启发式/强化学习求解器，通过**六大领域智能体 + 自然语言编排器**，实现「排程计算 → 执行仿真 → 异常重排 → 交期承诺 → 资源协同」的闭环。

### 2.2 产品定位

| 维度 | 说明 |
|------|------|
| **领域** | 离散制造、多品种小批量、作业车间（Job Shop） |
| **形态** | Web 应用（FastAPI 后端 + Vue3 前端 + MongoDB） |
| **差异化** | 算法工具箱（MetaForge）+ LLM 编排（智谱 GLM）+ 确定性 Tool 执行，兼顾可解释与可落库 |
| **交付形态** | 本仓库 `metaforge_agent`：算法库 + MES Web + 多智能体助手 |

### 2.3 核心价值主张

1. **可用**：录入/导入工单与工艺 → 一键多算法排程 → 甘特可视化 → 计划落库  
2. **可控**：策略权重（交期/能耗/负载均衡）可调，结果可复现、可对比  
3. **可变**：设备故障、插单、改交期、停机等事件触发 R0/R1/R2 重排与影响评估  
4. **可承诺**：交期风险、对客户话术、重排前后承诺变化可查询  
5. **可对话**：车间人员用自然语言驱动排程、重排、计划库操作，无需记忆 API  

### 2.4 业务闭环（目标态）

```mermaid
flowchart LR
  A[订单/计划录入] --> B[智能排程]
  B --> C[MES 执行仿真]
  C --> D[监控与异常]
  D --> E[动态重排]
  E --> F[交期承诺与汇报]
  F --> A
```

当前版本：**A→B→C→D→E** 已打通；**F** 在助手与报表中部分实现；BOM 进求解、完整 RBAC 为后续迭代。

## 4. 问题陈述与竞品参照

### 4.1 要解决的核心痛点

- 传统 APS：**门槛高**（需懂算法与参数）、**交互差**（表单密集）  
- 纯 LLM 方案：**不可复现**、难以对接真实甘特与落库  
- 单一求解器：**无法**按业务场景切换策略与对比  
- 静态排程：**无法**在故障/插单后快速评估影响与重排  

### 4.2 本产品解决思路

- **LLM 负责理解、规划、表述**；**Tool/Service 负责确定性计算**（甘特、R0/R1/R2、物料仿真）  
- **编排器统一入口**，六个领域 Agent 各司其职，避免多 Agent 串话混乱  
- **双入口**：助手 SSE + 看板 REST，同一重排内核

### 5.2 可量化成功指标（建议验收）

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 排程 API 成功率 | ≥99%（标准算例） | 不含 LLM 超时 |

## 6. 范围定义

### 6.1 范围内（In Scope）

- 作业车间（JSSP）排程与可视化（甘特、收敛曲线）  
- 计划库（MongoDB）：新建、绑定、列表、重命名、复制、状态、删除  
- 多算法对比与策略权重（makespan、加权拖期、能耗、负载 CV）  
- MES 生产执行仿真：`baseline_gantt`、`sim_time`、执行启停  
- 异常事件：设备故障、插单、改交期、计划停机、物料延迟、取消工单等  
- 影响评估：R0 原计划 / R1 故障不重排 / R2 冻结已开工+重排  
- 六大智能体 + 编排器（SSE 流式、预览模式）  
- 资源视图：能耗、设备健康、厂内物流（AGV）、人员、物料  
- 数字孪生快照（机器/AGV/人员状态汇总）  
- 人机确认（HITL）覆盖已有排程时的落库确认  

### 6.2 范围外（Out of Scope — 当前版本）

| 项 | 说明 | 规划参考 |
|----|------|----------|
| HFSP 混合流水车间 | 搁置 | 改进计划 |
| BOM/物料约束进求解器内核 | 当前为排程后分析 | M1 里程碑 |
| 完整 RBAC / 多租户 | 仅最小审计日志 | P5-D |
| MCP 外部工具适配 | 默认关闭 | `MCP_ENABLED=0` |
| 移动端原生 App | 仅 Web 响应式 | — |
| 云端 SaaS 多实例运维 | 本机/私有化部署为主 | — |

## 8. 功能需求详述

### 8.1 FR-01 计划库管理（Agent: `plans`）

| ID | 需求 | 验收标准 |
|----|------|----------|
| FR-01-1 | 用户可通过助手或界面新建、查看、列出、重命名、复制、改状态、删除计划 | 各操作对应 Tool 成功；查看/加载后跳转 APS |

### 8.2 FR-02 智能排程（Agent: `scheduling`）

| ID | 需求 | 验收标准 |
|----|------|----------|
| FR-02-1 | 支持自然语言指定算法（TS/GA/SA/ACO/规则等）与策略 | `scheduling.parse_intent` 结构化成功 |

| FR-02-4 | 排程结果可写回计划库（含 HITL 覆盖确认） | `data.propose_persist` + 确认流 |
| FR-02-5 | 支持异步排程（长任务） | `POST /api/run/async` + 轮询 |

### 8.3 FR-03 异常重排（Agent: `events`）

| ID | 需求 | 验收标准 |
|----|------|----------|

## 10. 非功能需求（NFR）

### 10.1 性能

| 项 | 要求 |
|----|------|
| 同步排程 | 中小规模（≤20 工单）目标 ≤30s |
| 长任务 | 提供异步接口，前端轮询状态 |
| LLM 调用 | 默认超时 60s（`LLM_TIMEOUT_SEC`），超时走规则回退 |

### 10.2 可用性与可靠性

- MongoDB 不可用时，核心写操作应明确失败提示  
- 编排器单步 Tool 失败应返回可追溯错误（trace + artifact）  
- 排程覆盖已有结果时必须 HITL 确认，禁止静默覆盖  

### 10.3 安全与合规

| 项 | 当前 | 目标 |
|----|------|------|
| 认证 | 开发环境无登录 | 企业部署需接入 SSO |
| 授权 | 无细粒度 RBAC | 角色：计划员/主管/只读 |
| 审计 | 可选 `AUDIT_LOG_ENABLED` | 关键操作全量审计 |
| 密钥 | `GLM_API_KEY` 等环境变量 | 禁止入库、禁止提交 Git |

### 10.4 可维护性

- 算法与 Web 解耦：`src/metaforge` 可独立 `pip install -e .`  
- 路由版本可核对：`ROUTER_BUILD_ID`、`GET /api/llm/status`  
- 文档索引：`docs/README.md`  

### 10.5 兼容性

| 项 | 要求 |
|----|------|
| 浏览器 | Chrome / Edge 最新两个大版本 |
| OS | Windows 10/11（交付脚本以 PowerShell 为主） |
| Python | 3.10+ 推荐 |
| Node | 用于前端构建（Vue3 + Vite） |

## 11. 用户旅程（端到端）

### 11.1 旅程 A：从零到排程落库

1. 打开 **数据中心** → 新建或导入计划工单  
2. 进入 **排程中心** → 选择算法与权重 → 运行排程  
3. 查看甘特与指标 → 确认后保存到计划库  
4. （可选）在 **智能助手** 说：「用遗传算法排产并保存到数据库」  

### 11.2 旅程 B：MES 执行与故障重排

1. **生产看板** → 加载计划 → **开始执行**（MES）  
2. 仿真进行中 → 触发「3 号机故障 4 小时」  
3. 使用看板 **异常重排** 或助手描述故障  
4. 查看 **影响评估**（R0/R1/R2）与承诺变化  
5. 在 **分析报表** 复核延期明细  

### 11.3 旅程 C：纯自然语言（助手）

1. 打开 **智能助手**  
2. 输入：「列出所有计划」→ 路由 `plans`  
3. 输入：「加载计划试产01」→ 跳转 APS  
4. 输入：「3 号机坏了 4 小时帮我重排」→ 路由 `events`（需 MES 已启动）

## 15. 术语表

| 术语 | 说明 |
