## 3. 架构（当前实现）

```text
用户 / 前端
    │
    ▼
POST /api/orchestrator/run  ──► Intent Router（关键词 / intent）
    │                              │
    │                              ▼
    │                    唯一主责 Agent（6 选 1）
    │                              │
    │                              ▼ Plan-and-Solve（GLM 优先 + 规则回退）
    │                    白名单 Tool 调用链
    │
    └── 也可直连 POST /api/agents/{id}/run
```

**原则（与设计一致）：**

- 一个用户意图 → **一个**业务 Agent（Router 不串多 Agent）
- Agent 薄层；重计算在 Tool / 现有 `compare_solvers`、events 服务
- Tool 先行；LLM 仅预留 schema（`GET /api/tools/registry`）

## 10. 已知限制与后续建议

1. **LLM**：主路径 GLM（Router / Plan / Parse）；失败时规则回退（`LLM_FALLBACK=rule`）。
2. **Session**：`SESSION_STORE=mongo` 时落库；`memory` 时进程重启丢失。
3. **HITL token**：与 Session 共用 `SESSION_STORE`，mongo 模式重启仍有效（15 分钟 TTL）。
4. **权限审计（P5-D）**：最小 `audit_log` 已接；完整 RBAC 待定。
5. **HFSP**：仍搁置。
6. **路由验收**：`tests/test_router_phrases.py`（20 条话术，规则路径）。
