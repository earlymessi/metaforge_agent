# MetaForge MES 技术报告（用于后续改进）

> 本报告基于当前仓库实现整理，重点面向“后续系统迭代与重构参考”。  
> 后端入口：`tests/main.py`（FastAPI）  
> 前端页面：`tests/templates/index.html`（静态页面，由后端 `/` 返回）

---

## 1. 系统概述

### 1.1 目标与范围

当前系统实现了一个轻量级 **MES（制造执行）/调度决策演示系统**，以 Job Shop Scheduling（JSSP）为核心问题域，提供：

- **工单/排程方案管理**：保存、查询、删除、状态更新
- **排程计算**：调用 MetaForge 算法能力执行求解与对比
- **资源/能耗配置**：分时电价、设备功率、维护阈值的配置与初始化
- **厂内物流（AGV）与人员/物料**：基础数据维护与分析/预测接口
- **数字孪生快照**：汇总机器/AGV/人员状态，用于前端可视化展示

### 1.2 运行形态

- 单进程 FastAPI 应用（开发模式启用 `reload=True`）
- MongoDB 作为持久化存储（Motor 异步驱动）
- 前端为单个静态 HTML 页面，通过 `fetch('/api/...')` 调用后端

## 2. 技术栈与依赖

### 2.1 后端

- **Web 框架**：FastAPI
- **ASGI Server**：Uvicorn
- **数据校验/建模**：Pydantic
- **数据库**：MongoDB
- **MongoDB 驱动**：Motor（底层 PyMongo）
- **跨域**：CORS 全开（`allow_origins=["*"]` 等）

### 2.2 算法/业务域（MetaForge 库）

通过 `src/metaforge/` 提供：

- JSSP 数据结构：`metaforge.problems.jobshop.JobShopProblem / Job / Task`
- 算法运行入口：`metaforge.metaforge_runner.run_solver`
- 求解器对比：`metaforge.utils.compare_solvers.compare_solvers`
- 可视化工具：`metaforge.utils.visualization.plot_gantt_chart`

### 2.3 前端

- 单页静态 HTML（`tests/templates/index.html`）
- 主要依赖 CDN：Bootstrap、FontAwesome、Google Fonts（离线交付需本地化）
- 使用 `fetch()` 调用后端接口

## 5. 数据库设计（MongoDB）

> 说明：当前为“集合级”设计文档，字段以代码/使用场景为依据归纳；后续建议补充索引与约束（见第 9 节改进建议）。

### 5.1 集合清单

在 `tests/main.py` 中定义/使用的集合：

- `work_orders`：工单/排程方案（保存 jobs、排程结果、图表）
- `maintenance_orders`：维护工单（预留/扩展）
- `agv_fleet`：AGV 车队状态（`agv_id/location/status`）
- `agv_tasks`：AGV 搬运任务历史
- `staff_roster`：人员花名册与在岗状态
- `materials_inventory`：物料库存
- `tools_library`：工装/刀具库（预留/扩展）
- `machines_layout`：机器布局（含 3D 坐标与状态）
- `resource_config`：能耗配置（`_id="global_config"` 的单文档配置）

### 5.2 关键文档结构（建议口径）

#### 5.2.1 `work_orders`

代码模型：`WorkOrderSchema`

- `plan_name`: string（方案/计划名）
- `jobs`: Job 列表
  - `name`: string
  - `priority`: int（默认 10，100 为加急）
  - `tasks`: Task 列表
    - `machine_id`: int
    - `duration`: int
    - `name`: string|null
- `created_at`: datetime
- `status`: string（默认 `pending`）
- `schedule_result`: object|null（排程算法结果）
- `chart_image`: string|null（Base64 图片）

#### 5.2.2 `resource_config`

用途：能耗配置初始化与读取（若无则插入默认值）

- `_id`: `"global_config"`
- `machine_powers`: `{[machineId: string]: number}`（kW）
- `hourly_prices`: `number[24]`（分时电价）
- `maintenance_limits`: `{[machineId: string]: number}`（阈值）

#### 5.2.3 `machines_layout`

初始化会写入 12 台机器坐标：

- `id`: int
- `name`: string
- `x/y/z`: number（3D 坐标）
- `status`: string（默认 `idle`）

## 6. 后端接口设计（FastAPI）

### 6.1 通用约定

- Base URL：`http://127.0.0.1:8000`
- Content-Type：JSON（除 `/` 返回 HTML）
- 错误处理：部分接口使用 `HTTPException`；整体建议统一错误结构（见第 9 节）

### 6.2 页面与基础能力

#### 6.2.1 `GET /`

- **用途**：返回前端页面 `tests/templates/index.html`；不存在则返回 `{"message": "MetaForge Backend Running"}`

#### 6.2.2 `GET /api/benchmarks`

- **用途**：扫描 `tests/data/benchmarks/*.txt` 并返回文件列表
- **返回**：
  - `{ "files": ["ft06.txt", "..."] }`

#### 6.2.3 `GET /api/resources/config`

- **用途**：获取能耗配置；若数据库不存在则初始化默认配置写入 `resource_config`
- **返回**：`resource_config` 文档（含 `_id/machine_powers/hourly_prices/maintenance_limits`）

### 6.3 工单/方案（数据库 API）

#### 6.3.1 `POST /api/db/save`

- **用途**：保存工单/排程方案（支持保存排程结果与图表 base64）
- **请求体**：`WorkOrderSchema`
- **典型返回**：包含插入后的 `id`（ObjectId 字符串）或保存结果（以实现为准）

#### 6.3.2 `GET /api/db/list`

- **用途**：列出已保存的工单/方案
- **返回**：列表（每项包含 `id` 及工单摘要/内容）

#### 6.3.3 `DELETE /api/db/delete/{oid}`

- **用途**：按 ObjectId 删除方案
- **路径参数**：
  - `oid`: string（ObjectId）

#### 6.3.4 `POST /api/db/status/{oid}`

- **用途**：更新方案状态（例如 pending/running/done）
- **路径参数**：
  - `oid`: string
- **请求体**：
  - `{ "status": "..." }`（模型 `StatusUpdate`）

### 6.4 看板/统计

#### 6.4.1 `GET /api/dashboard/stats`

- **用途**：提供看板统计数据（前端用于 dashboard 展示）
- **返回**：统计 JSON（以实现为准）

### 6.5 排程运行

#### 6.5.1 `POST /api/run`

- **用途**：执行排程计算，支持基准算例或自定义工单数据
- **请求体**：`CompareRequest`
  - `solvers`: `string[]`（求解器名称列表）
  - `benchmark_file`: string|null（基准算例文件名）
  - `custom_data`: Job 列表|null（自定义工单数据）
- **返回**：包含每种求解器的结果、最佳 makespan、调度序列/图表等（以实现为准）

> 备注：该接口是“核心计算入口”，后续改进多集中于：参数校验、可观测性、任务异步化、结果缓存、并发控制。

### 6.6 人员（Staff）

#### 6.6.1 `GET /api/staff/list`

- **用途**：获取人员花名册

#### 6.6.2 `POST /api/staff/toggle/{uid}`

- **用途**：切换人员是否在岗（`is_active`）
- **路径参数**：
  - `uid`: int（人员 id）

#### 6.6.3 `POST /api/staffing/analyze`

- **用途**：人员配置分析（前端用于“人力分析”功能）
- **请求体/返回**：以实现为准（建议后续补齐接口契约示例）

### 6.7 厂内物流（AGV）

#### 6.7.1 `POST /api/logistics/generate`

- **用途**：生成物流/搬运任务并分配 AGV（前端用于物流模拟）
- **请求体/返回**：以实现为准

### 6.8 物料（Materials）

#### 6.8.1 `GET /api/materials/list`

- **用途**：物料库存列表

#### 6.8.2 `POST /api/materials/predict`

- **用途**：物料消耗/补货预测（前端用于预测与告警）
- **请求体/返回**：以实现为准

#### 6.8.3 `POST /api/materials/restock/{mid}`

- **用途**：指定物料补货/入库动作
- **路径参数**：
  - `mid`: string（物料 id，如 `MAT_STEEL`）

### 6.9 数字孪生

#### 6.9.1 `GET /api/digital_twin/snapshot`

- **用途**：汇总机器/AGV/人员快照，供前端 3D/看板展示
- **返回**：
  - `machines`: 机器快照（含坐标、状态等）
  - `agvs`: AGV 坐标与状态
  - `staff`: 在岗人员坐标信息
  - `meta`: 元信息（例如时间戳/统计数据等）

## 8. 关键流程（数据流/调用链）

### 8.1 系统启动（lifespan）

1. 创建 MongoDB client，执行 `ping` 验证连通性
2. 初始化基础数据（若集合为空则插入默认数据）：
   - AGV 车队、人员花名册、物料库存、机器布局（3D 坐标）

### 8.2 排程运行（典型）

1. 前端提交：选择求解器、选择基准算例或自定义工单
2. 后端 `/api/run`：
   - 解析请求 → 构造 `JobShopProblem`
   - 调用 `compare_solvers`/`run_solver` 执行求解
   - 生成结果（可包含甘特图/统计信息）
3. 前端展示结果，并可调用 `/api/db/save` 保存方案

### 8.3 数字孪生刷新

1. 前端轮询或手动触发 `GET /api/digital_twin/snapshot`
2. 后端聚合 `machines_layout`、`agv_fleet`、`staff_roster` 等数据并返回

## 9. 后续改进建议（建议按优先级推进）

### 9.1 架构与代码组织

- **将 `tests/main.py` 拆分为正式应用模块**：建议迁移到 `src/metaforge_mes/` 或 `src/metaforge/api/`，并将 `tests/` 仅保留测试。
- **引入配置层**：统一管理端口、Mongo 连接、日志级别、CORS 白名单等。
- **接口契约文档化**：为每个接口补齐请求/响应示例与错误码（可自动生成 OpenAPI + 补充说明）。

### 9.2 数据库与数据一致性

- **索引**：为 `work_orders.created_at/status/plan_name` 等建立索引；为 `materials_inventory.id`、`staff_roster.id` 建唯一索引。
- **枚举与约束**：例如 `status` 字段限定集合；避免前端写入任意字符串。
- **迁移/版本**：引入简单的 schema version 字段，方便后续演进。

### 9.3 可靠性与可观测性

- **统一错误返回格式**：例如 `{code, message, detail, trace_id}`，前端统一处理。
- **日志与追踪**：关键接口（尤其 `/api/run`）增加耗时、输入规模、求解器名、异常栈记录。
- **任务异步化**：排程计算可改为后台任务（Celery/RQ/BackgroundTasks），前端轮询任务状态，避免请求超时。

### 9.4 安全与交付

- **CORS 收敛**：从全开放改为白名单。
- **鉴权**：交付/上线环境建议增加最小权限控制（Token/Basic Auth）。
- **前端资源本地化**：替换 CDN 依赖，保障离线/内网环境可用。
